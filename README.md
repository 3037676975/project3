# Payment Lab 通用支付模板

> 一个可复制、可扩展的支付宝 + 微信支付 PHP 模板项目。

## 项目定位

`project3` 不是一个支付接口平台，而是一个**支付功能开发模板**。

以后开发任何新网站，只需要参考：

```
参考 project3 支付模板接入支付
```

即可按照本项目的结构快速加入支付宝、微信支付能力。

本项目采用：

- 独立支付模块
- 独立配置管理
- 统一订单结构
- 统一支付日志
- 后台可视化管理

不要求新项目调用本项目接口，而是复制支付模块结构。

---

# 已支持能力

## 支付宝

支持：

- 支付宝当面付
- PC 扫码支付
- 移动端支付扩展
- 创建支付订单
- 生成真实二维码
- 异步通知处理
- 订单查询
- 支付状态更新
- RSA2 签名验证

## 微信支付

支持模板：

- Native 扫码支付
- H5 支付扩展
- JSAPI 扩展
- 回调通知
- 订单查询
- 状态同步

# 新项目接入方式

## 第一步：复制支付模块

复制：

```
app/payment
```

到你的新项目。

---

## 第二步：接入业务订单

例如：

会员充值：

```
用户购买会员
        ↓
创建业务订单
        ↓
调用支付模块
        ↓
用户付款
        ↓
支付回调
        ↓
更新会员状态
```

商城：

```
创建商品订单
        ↓
调用支付
        ↓
付款成功
        ↓
发货
```

# 支付配置原则

不要把密钥写入代码。

支付宝：

```
APPID
应用私钥
支付宝公钥
回调地址
```

微信：

```
商户号
AppID
API密钥
回调地址
```

全部通过后台配置保存。

---

# 订单标准

所有项目建议统一订单结构：

```
订单号
商品名称
金额
支付方式
支付状态
第三方交易号
创建时间
支付时间
```

这样任何业务系统都可以复用。

# 支付模块规范

推荐结构：

```
app/payment

├── alipay
│   ├── create.php
│   ├── query.php
│   └── notify.php
│
└── wechat
    ├── create.php
    ├── query.php
    └── notify.php
```

要求：

- 支付请求必须记录日志
- 回调必须验签
- 状态更新必须幂等
- 不重复发货

# 宝塔部署

环境要求：

- PHP 8.0+
- Nginx
- OpenSSL
- CURL

部署：

1. 拉取 GitHub 仓库
2. 网站目录设置：

```
/public
```

3. 设置 storage 可写
4. 填写支付配置
